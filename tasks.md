# Задачи

## Сессия 2 — ядро

- [ ] Типы матрицы: ожидаемая матрица доступа (`ExpectedAccess`) отдельно от наблюдённой.
- [ ] Чистая функция построения фактической матрицы из наблюдений.
- [ ] Чистая функция диффа: ожидаемое против фактического, с классификацией расхождений.
- [ ] Фикстуры в `tests/fixtures`: минимум два тенанта, три роли, набор эндпоинтов.
- [ ] Покрытие ядра тестами; подключить `@vitest/coverage-v8` и пороги покрытия
      (провайдер намеренно не ставился в сессии 1 — покрывать было нечего).

## Сессия 3 — адаптеры

- [ ] Реализация `SpecParser` на `@apidevtools/swagger-parser` с `resolve: { file: false, http: false }`.
- [ ] **Блокирующее:** тест-доказательство, что внешние `$ref` не резолвятся — отдельно
      для `http(s)://` и для `file://` / относительного пути. Без него адаптер не принимается.
- [ ] Тест на YAML-бомбу: лимит размера и глубины входного документа.
- [ ] Реализация `HttpClient` на встроенном global fetch (не отдельный undici).
- [ ] Реализация `Throttle`: конкурентность, RPS, потолок на прогон, экспоненциальный
      backoff, circuit breaker на серии 5xx/429, уважение `Retry-After`.
- [ ] Проверить и добавить пакеты: `@apidevtools/swagger-parser`, `p-limit`, `p-queue`
      (возраст релиза, мейнтейнеры, транзитив, provenance).

## Сессия 4 — CLI и вывод

- [ ] Обязательный allowlist хостов: без него инструмент отказывается работать.
- [ ] Флаг `--unsafe-methods`; по умолчанию только GET и HEAD.
- [ ] JSON-отчёт как единственный источник истины.
- [ ] Редакция чувствительных данных по хардкод-путям (`fast-redact` или `@pinojs/redact`;
      учесть, что `fast-redact` мутирует исходный объект).
- [ ] Версия CLI из `package.json` вместо константы `VERSION` в `src/cli.ts`.
- [ ] Проверить и добавить пакеты: `zod`, `pino`, `fast-redact`, `picocolors`.

## Сессия 5+ — integration

- [ ] docker-compose с полигоном, у которого есть переключаемые дефекты, — для валидации
      на известном ground truth (в том числе на отсутствие ложных срабатываний).
- [ ] Машиночитаемый ground-truth с ожидаемой матрицей доступа.

## Инфраструктура, не срочно

- [ ] Решить вопрос публикации: npm trusted publishing (OIDC) + provenance. Не раньше,
      чем появится работающее ядро.
- [ ] Changesets для версионирования — когда появится что версионировать.
- [ ] OSV-Scanner в CI как дополнительный слой аудита.
- [ ] Пересмотреть TypeScript 7, когда выйдет из preview и стабилизирует публичный API.
