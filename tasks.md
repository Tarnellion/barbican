# Задачи

Фазы и критерии выхода — в [plan.md](plan.md).

## Сессия 2 — ядро (закрыта)

- [x] **ADR-0006:** ожидаемая матрица объявляется человеком, а не выводится из спеки.
- [x] Типы политики (`ExpectedAccessPolicy`) отдельно от наблюдённой матрицы.
- [x] `buildAccessMatrix` — сборка с проверкой целостности входа.
- [x] `diffAccess` — дифф с классификацией: эскалация, неожиданный отказ,
      непокрытая пара, ошибка обращения.
- [x] Фикстуры: два тенанта, три роли, четыре эндпоинта, «чистый» набор наблюдений.
- [x] `@vitest/coverage-v8` и пороги покрытия ядра, гейт в CI.

Осталось из этой темы:

- [ ] Селекторы эндпоинтов по шаблону метода и пути, а не только по списку `id`.
      На сотне эндпоинтов перечисление станет неподдерживаемым.
- [ ] Обнаружение cross-tenant утечек. Требует привязки ресурса к тенанту, а её
      неоткуда взять, пока не решён вопрос сбора идентификаторов (фаза 2).

## Сессия 3а — парсер спецификаций (закрыта 12 августа 2026)

- [x] `SpecParser` на `@apidevtools/swagger-parser` с `resolve: { external: false }`.
      Порт принимает **текст документа**, а не путь: парсеру нечего открывать.
- [x] **Блокирующее:** тесты-доказательства. Проверяют не «выбросилась ли ошибка»,
      а что обращения наружу не произошло — http-сервер не получил ни одного запроса,
      содержимое файла не попало в результат.
- [x] Защита от YAML-бомбы через `maxAliasCount`, плюс пределы размера и глубины.
- [x] Проверены и добавлены `yaml` 2.9.0 и `@apidevtools/swagger-parser` 12.1.0.

Проверено экспериментом: барьеры закрывают разное. `resolve.external = false` —
защита от SSRF (со снятой явной проверкой запрос всё равно не уходит), а явный отказ
на внешнем `$ref` — защита от тихой деградации, потому что иначе swagger-parser
возвращает результат без ошибки с неразрешённой ссылкой.

## Сессия 3б — HTTP и троттлинг (закрыта 12 августа 2026)

- [x] `Throttle`: конкурентность, скользящее окно частоты, потолок на прогон.
      Своя реализация вместо `p-queue` — обоснование в ADR-0001.
- [x] `HttpClient` на встроенном global fetch: обязательный allowlist хостов,
      только `SAFE_METHODS` без явного разрешения, `redirect: "manual"`,
      тело не читается, чувствительные заголовки редактируются.
- [x] Экспоненциальный backoff с джиттером, приоритет `Retry-After`,
      circuit breaker на серии 5xx/429.
- [x] Пороги покрытия для `src/adapters` — отдельно от ядра, чтобы стопроцентное
      ядро не маскировало просадку адаптеров.

Проверено экспериментом: с `redirect: "follow"` запрос действительно уходит на хост
вне allowlist. Это не теоретический риск, а работающий обход области проверки.

Осталось из этой темы:

- [ ] Ретраи и circuit breaker сейчас живут в HTTP-клиенте. Если появится второй
      транспорт, вынести в декоратор над портом.
- [ ] Проверять allowlist ещё и по порту, а не только по имени хоста.

## Сессия 4 — CLI и вывод (закрыта 12 августа 2026)

- [x] **ADR-0008:** формат конфигурации. Один файл YAML или JSON; учётные данные
      в нём не хранятся — аккаунт называет переменную окружения.
- [x] `src/io/config.ts`: разбор и проверка через `zod`, обязательный `allowedHosts`,
      хост из `baseUrl` обязан в него входить.
- [x] `src/runner.ts`: обход матрицы «аккаунт × эндпоинт», сведение статуса к выводу
      о доступе, явный список пропущенного и сорвавшегося.
- [x] `src/report/build.ts`: JSON-отчёт и код возврата.
- [x] CLI `barbican run` со связыванием и флагами троттлинга.
- [x] Сквозные тесты: подложенный дефект находится, на чистом стенде находок нет.

Проверено запуском собранного CLI против живого сервера: эскалация найдена, код
возврата 1, ни токенов, ни `set-cookie` в отчёте.

Осталось из этой темы:

- [ ] Схема аутентификации захардкожена как `Authorization: Bearer`. Вынести
      в конфигурацию, когда появится цель с другой схемой.
- [ ] Эндпоинты с параметрами в пути не опрашиваются. Снимается вместе с решением
      о сборе идентификаторов (фаза 2).
- [ ] `picocolors`, `pino` и `fast-redact` не понадобились: цвет даёт встроенный
      `node:util styleText`, а токенов в отчёте нет по конструкции.

## Фаза 2 — валидация на публичных полигонах

- [ ] **ADR (блокирующее для этого класса детекторов):** сбор идентификаторов из тел
      ответов против запрета хранить тела. Часть BOLA достижима только по `id` из
      предыдущего ответа. Направление: извлечение отдельных значений по заданным в коде
      путям в кратковременный пул в памяти, не попадающий в отчёт.
- [ ] **ADR:** единый формат машиночитаемого ground-truth — общий для VAmPI, crAPI
      и своей платформы, иначе валидация не переиспользуется.
- [ ] docker-compose с VAmPI. Прогон с **выключенными** уязвимостями обязан дать ноль
      находок — это первичный критерий, важнее обнаружения.
- [ ] Прогон против crAPI, сверка с задокументированными BOLA/IDOR.
- [ ] Juice Shop — по остаточному принципу.

## Фаза 3 — мультитенантность

- [ ] Минимальная референс-платформа: 3–4 эндпоинта, два тенанта, три переключаемых
      через env дефекта (отсутствующий фильтр по тенанту, отключаемая проверка роли,
      IDOR по прямому идентификатору). Нужен оракул, а не платформа.
- [ ] Машиночитаемый ground-truth с ожидаемой матрицей доступа.

## Фаза 4 — стабилизация и публикация

- [ ] Вернуть `publishConfig.provenance: true` в package.json. Снято при первой
      публикации: provenance требует OIDC от CI и ломает публикацию с ноутбука.
- [ ] npm trusted publishing (OIDC) + provenance. Требует npm CLI >= 11.5.1
      (локально сейчас 10.9.4).
- [ ] Changesets для версионирования.
- [ ] Документация пользователя: аккаунты, ожидаемая матрица, scope.
