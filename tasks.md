# Задачи

Фазы и критерии выхода — в [plan.md](plan.md).

## Сессия 2 — ядро (закрыта)

- [x] **ADR-0006:** ожидаемая матрица объявляется человеком, а не выводится из спеки.
- [x] Типы политики (`ExpectedAccessPolicy`) отдельно от наблюдённой матрицы.
- [x] `buildAccessMatrix` — сборка с проверкой целостности входа.
- [x] `diffAccess` — дифф с классификацией: эскалация, неожиданный отказ,
      непокрытая пара, ошибка обращения.
- [x] Фикстуры: два тенанта, три роли, четыре эндпоинта, «чистый» набор наблюдений.
- [x] `@vitest/coverage-v8` и пороги покрытия ядра, гейт в CI.

Осталось из этой темы:

- [x] Селекторы эндпоинтов по шаблону метода и пути. Элемент правила — либо
      идентификатор, либо `{ method?, path }`; `*` внутри сегмента, `**` через.
      Шаблоны раскрываются в идентификаторы **до** диффа, поэтому `resolveExpected`
      и проверка достоверности не тронуты вовсе.
- [x] Объявленная и раскрытая политика — **разные типы**. Раскрытая присваивается
      объявленной, но не наоборот, поэтому передать нераскрытую туда, где нужна
      раскрытая, компилятор не даёт. Иначе шаблон дожил бы до сравнения и молча
      не совпал ни с чем. Компилятор поймал ровно этот случай в CLI.
- [x] Шаблон, не совпавший ни с одним эндпоинтом, останавливает прогон: правило
      не применилось бы ни разу, пары ушли бы в `fallback`, отчёт остался бы
      чистым. Проверено на платформе — опечатка даёт код 2 до первого запроса.
- [x] Платформа переведена на шаблон в правиле администратора: 19 комбинаций
      сошлись ячейка в ячейку, то есть шаблон выражает ровно то же множество.
- [x] Обнаружение cross-tenant утечек — ADR-0010, матрица стала трёхмерной.

## Сессия 3а — парсер спецификаций (закрыта 12 августа 2026)

- [x] `SpecParser` на `@apidevtools/swagger-parser` с `resolve: { external: false }`.
      Порт принимает **текст документа**, а не путь: парсеру нечего открывать.
- [x] **Блокирующее:** тесты-доказательства. Проверяют не «выбросилась ли ошибка»,
      а что обращения наружу не произошло — http-сервер не получил ни одного запроса,
      содержимое файла не попало в результат.
- [x] Защита от YAML-бомбы через `maxAliasCount`, плюс пределы размера и глубины.
- [x] Проверены и добавлены `yaml` 2.9.0 и `@apidevtools/swagger-parser` 12.1.0.

Проверено экспериментом: барьеры закрывают разное. `resolve.external = false` —
защита от SSRF (со снятой явной проверкой запрос всё равно не уходит), а явный отказ
на внешнем `$ref` — защита от тихой деградации, потому что иначе swagger-parser
возвращает результат без ошибки с неразрешённой ссылкой.

## Сессия 3б — HTTP и троттлинг (закрыта 12 августа 2026)

- [x] `Throttle`: конкурентность, скользящее окно частоты, потолок на прогон.
      Своя реализация вместо `p-queue` — обоснование в ADR-0001.
- [x] `HttpClient` на встроенном global fetch: обязательный allowlist хостов,
      только `SAFE_METHODS` без явного разрешения, `redirect: "manual"`,
      тело не читается, чувствительные заголовки редактируются.
- [x] Экспоненциальный backoff с джиттером, приоритет `Retry-After`,
      circuit breaker на серии 5xx/429.
- [x] Пороги покрытия для `src/adapters` — отдельно от ядра, чтобы стопроцентное
      ядро не маскировало просадку адаптеров.

Проверено экспериментом: с `redirect: "follow"` запрос действительно уходит на хост
вне allowlist. Это не теоретический риск, а работающий обход области проверки.

Осталось из этой темы:

- [ ] Ретраи и circuit breaker сейчас живут в HTTP-клиенте. Если появится второй
      транспорт, вынести в декоратор над портом.
- [x] Allowlist различает записи с портом и без: `api.test` разрешает любой порт,
      `api.test:8443` — ровно один.
- [x] Circuit breaker считает неудачные обращения, а не попытки. Раньше при
      дефолтах прогон вставал после двух обращений вместо пяти.
- [x] `pnpm run check` включает гейт покрытия — тот же, что в CI. Раньше локальная
      проверка говорила «всё хорошо» там, где CI падал.

## Фаза 2 — валидация на публичных полигонах

- [x] **ADR-0009:** оракул — написанный вручную список известных дефектов, а не
      переключатель полигона. Измерено: режимы VAmPI неразличимы по статусам.
- [x] Прогон против настоящего VAmPI. Найдены три настоящих расхождения; по итогам
      исправлены два дефекта самого инструмента (см. ниже).
- [x] **ADR-0012:** единый формат оракула. За основу взята форма VAmPI как более
      полная: находка ссылается на именованный дефект, у дефекта есть признак
      видимости (`status` / `body-signal` / `invisible`).
- [x] Обе сверки переписаны на общий модуль `tools/oracle/`: разбор формата,
      сравнение множествами в обе стороны, проверки достоверности и проверка
      полноты оракула. Модуль покрыт 21 тестом — он несущий для всех
      утверждений вида «расхождений 0».
- [x] Платформа: 19 вариантов сошлись после переписывания. VAmPI: 2 режима,
      13 и 11 находок — те же, что до него.
- [x] **Формат поправлен дважды по ходу переноса.** `defect` стал `defects`:
      у вложенных дефектов общая ячейка объясняется обоими, и приписать её
      одному значит объявить второй непроверяемым — проверка полноты выдала
      это сразу. Видимость выросла с трёх видов до шести: `invisible` стирал
      различие между четырьмя разными пробелами.
- [x] У crAPI появился машиночитаемый оракул в формате ADR-0012: 22 дефекта,
      каждый с объявленной видимостью, сверка через общий модуль. Проверена
      на падение подлогом в обе стороны — число находок осталось 16 против 16,
      на счёте сверка бы промолчала, множествами заметила.
- [x] Шесть видов видимости оправдали себя именно здесь: 6 `status`, 2 `body-only`,
      5 `unsafe-method`, 1 `excluded`, 8 `out-of-scope`. Один `invisible` стёр бы
      различие между четырьмя разными пробелами.
- [x] Пароли стенда переопределяются окружением. Значения не секретны — они
      опубликованы в самом crAPI, — но образец «пароль строкой» в репозитории
      не нужен: читатель копирует форму, а не оговорку.
- [x] `exclude: [create_service_report]` — **проверено по самой спецификации**
      13 августа 2026, а не принято по чтению агента: в `crapi-openapi-spec.json`
      у `GET /workshop/api/mechanic/receive_report` стоит `operationId:
      create_service_report` и summary «Create and Assign a Service Report».
      Запись за безопасным по букве методом — тот же класс, что `GET /createdb`.
- [x] Схлопывание в самом отчёте решено отдельно — ADR-0015, группировка по
      сигнатуре «эндпоинт × вид × отношение». На чужом стенде работает, потому
      что не требует объявленных дефектов; цена — нижняя граница вместо точного
      числа, и так и написано.
- [x] Прогон против VAmPI воспроизводим: `polygons/vampi/` с docker-compose,
      скриптом получения токенов и сверкой по обоим режимам. Расхождений 0.
- [x] **Вывод ADR-0009 опровергнут собственным условием пересмотра.** После
      подстановки в путь режимы VAmPI различимы по статусу на `GET /books/v1/{book_title}`
      (200 против 404). Прежнее «отчёты совпадают побайтово» измеряло слепоту
      инструмента, а не свойство полигона. Решение устояло, измерение — нет;
      датированное уточнение в ADR-0009.
- [x] Подстановка значений в шаблонные пути.
- [x] Неаутентифицированный аккаунт: `tokenEnv` стал необязательным.
- [x] Разведка crAPI проведена на живом стенде — [docs/polygons/crapi.md](docs/polygons/crapi.md).
      Сейчас инструмент найдёт там 1 надёжный дефект (BFLA `management/users/all`),
      после подстановки идентификаторов — плюс 3 BOLA и 1 сломанную аутентификацию.
- [x] Подстановка в query-параметры. Объект с идентификатором в строке запроса
      привязывается к эндпоинту явным списком: по совпадению имён его не связать.
- [x] Прогон против crAPI: найдено всё, что помечено видимым по статусу — 6 классов
      дефектов, 0 ложных срабатываний. Подробности в [docs/polygons/crapi.md](docs/polygons/crapi.md).
- [x] **ADR-0015: группировка по сигнатуре** «эндпоинт × вид × отношение».
      Роль в сигнатуру не входит: открытая всем ручка — один дефект, не два.
      Отношение входит: BOLA внутри тенанта и межтенантная утечка живут на одной
      ручке, но ломаются независимо. На платформе 24 строки свелись к 4 сигнатурам.
- [x] Формулировка «не менее N»: группа из 12 ячеек на платформе — это на самом
      деле **два** дефекта (`cross-tenant` 10 + `cross-holding` 2) с разными
      ветками в коде и одинаковой сигнатурой снаружи. Нижняя граница, названная
      точным числом, была бы враньём в свою пользу.
- [x] **ADR-0014: серьёзность расхождений и семантика кодов возврата.**
      Серьёзность выводится из вида расхождения и отношения, а не объявляется:
      утечка в чужой тенант — `critical`, BOLA внутри тенанта и доступ к функции —
      `high`, доступ к собственному объекту — `medium` (почти всегда ошибка
      в политике, а не дыра). На платформе это дало 12 критических и 9 высоких
      вместо плоского списка из 21 строки.
- [x] **`unexpected-denial` теперь даёт код возврата 1.** Расхождение есть
      расхождение, куда бы оно ни было направлено; инструмент не может знать,
      что неверно — платформа или объявление, — а раз не может, то и молчать
      не вправе. Найдено проверкой оракула: холдингу закрыли его собственный
      бренд, и прогон вернул 0.
- [ ] Juice Shop — по остаточному принципу.
- [x] **Оба внешних полигона пересверены 13 августа 2026** после условий
      обращения, вердиктов в наблюдениях и правок отчёта: VAmPI — 2 режима,
      crAPI — 60 ячеек, 16 находок, расхождений 0. Заодно у обоих появилась
      `target.label`: отчёт crAPI не называл проверенную систему, а по моему же
      правилу по такому отчёту нельзя заводить тикет.
- [ ] Флак VAmPI: `GET /createdb` дважды подряд ответил 500, третий прогон
      прошёл без правок. Похоже на состояние контейнера, а не на инструмент —
      но если повторится, стоит перезапускать стенд между режимами.

Найдено прогоном против VAmPI и исправлено:

- [x] Отказ от небезопасного метода записывался в `failures` — штатная работа
      выглядела поломкой. Теперь это пропуск с причиной `unsafe-method`.
- [x] Список `exclude` в конфигурации. `SAFE_METHODS` защищает от семантики метода,
      но не от эндпоинта, её нарушающего: `GET /createdb` сбрасывает базу и был
      реально вызван инструментом.
- [x] Сводка CLI расшифровывает причины пропусков: одно число читалось как
      «что-то не проверено» без объяснения.

## Фаза 3 — мультитенантность

Модель принадлежности реализована (ADR-0010) и проверена сквозным прогоном:
на стенде с утечкой находятся обе стороны с указанием объекта и отношения,
на корректном стенде находок нет. Осталась платформа с переключаемыми дефектами.

- [x] Референс-платформа `polygon/`: 4 эндпоинта, два тенанта, три переключаемых
      через env дефекта. Ноль рантайм-зависимостей, слушает только `127.0.0.1`.
- [x] Машиночитаемый ground-truth на все 8 комбинаций флагов, написан от модели
      доступа вручную, а не снят с вывода инструмента. `verify.mjs` — сверка.
- [x] Все 8 комбинаций совпали с оракулом, расхождений 0. Ноль находок в чистом
      режиме здесь не даровое, в отличие от VAmPI: флаг включается — находки есть.
- [x] Оракул проверен на способность падать **подложенным в платформу** дефектом
      (админская ручка всем): 4 находки сверх оракула ровно в тех комбинациях,
      где дефект не объявлен, и чистый режим сменил код возврата с 0 на 1.
- [x] Дубль идентификатора объекта сообщал `DuplicateAccountIdError` и отправлял
      читателя в секцию `accounts`, где всё в порядке. Найдено при сборке платформы.

## Сигналы над телом ответа (закрыто 12 августа 2026)

- [x] **ADR-0011:** инвариант уточнён с «тело не читается» на «тело не сохраняется».
      Читается транзитно ради необратимых скаляров; `SignalValue` — только число
      или булево, поэтому тело в него структурно не помещается.
- [x] `src/adapters/signals.ts`: `digest` (48 бит, соль случайна на прогон),
      `count`, `present`. Путь — сегменты через точку, без выражений.
- [x] Потолок размера: сверх него сигналов нет вовсе. Дайджест по префиксу
      утверждал бы совпадение ответов, различающихся за отсечкой.
- [x] Проверка `identical-response-across-tenants` — первая в `CheckRegistry`,
      то есть архитектура ADR-0003 наконец проверена на деле, а не на словах.
- [x] Объявление `responseMustDifferByTenant` делается человеком; опечатка в нём
      ловится `assertReferencesResolve` — иначе отказ был бы молчаливым и закрытым.
- [x] Находка проверки влияет на код возврата: иначе прогон с найденной
      межтенантной утечкой выглядел бы в CI успешным.
- [x] Четвёртый дефект платформы: `GET /v1/orders` без фильтра по тенанту.
      Не меняет ни одного статуса. Оракул расширен до 10 комбинаций, все совпали.
- [x] Проверено мутациями: `Object.hasOwn` → `in`, потолок → префикс, тело
      подложено в сигнал в обход типов — каждая ловится. Мутация «соль по
      умолчанию пустая» **не ловилась**, пока не был дописан тест на умолчание.
- [x] Проверено снятием объявления `responseMustDifferByTenant`: 6 находок
      исчезают, код возврата падает с 1 до 0. Объявление несущее, а не декоративное.

Осталось из этой темы:

- [x] `count` и `present` объявляются в конфигурации (`bodySignals.signals`).
      Находок не порождают намеренно — потребитель у них человек, разбирающий
      находку дайджеста. Проверено на платформе: в чистом режиме каждый аккаунт
      видит 2 записи, с дефектом — 4. Счётчик находкой быть не может: в чистом
      режиме он у разных тенантов тоже совпадает, различает только дайджест.
- [x] Повтор имени сигнала отвергается: имена — ключи наблюдения, повтор молча
      затирал бы предыдущий скаляр.
- [x] crAPI перепрогнан с сигналами на живом стенде. Проверка изоляции
      промолчала — и это **правильный ноль, а не пропуск**: три списочные ручки
      помечены, тела прочитаны, дайджесты у разных пользователей различаются.
      crAPI фильтрует эти списки верно, искомого дефекта там просто нет.
      Доказано от противного: ошибочная пометка публичной ленты немедленно
      даёт 3 находки. Конфигурация прогона — `polygons/crapi/`.

- [ ] Новая честная граница: три уровня отличают шаг от цепочки, но не отличают

- [x] Оракул поймал мою собственную ошибку рассуждения: прежний дефект списка

      случаях. Шесть пар в семи комбинациях я не предусмотрел. Следствие
      записано в docs/report.md: две группы дефектов, отличающиеся только
      условиями, — почти наверняка одна поломка платформы.
- [x] `present` не видел поле внутри элемента списка и отвечал `false` вместо
      «сигнала нет» — неверный сигнал, неотличимый от честного отрицания.
      Числовой индекс в пути. Найдено ресерчем по аффилиатским кабинетам.
- [x] **Бренд по поддомену.** У тенанта появился свой `baseUrl`. Адрес
      выбирается по тенанту **объекта**, а не аккаунта: спрашиваем за чужие
      данные, лежат они на чужом хосте. Канарейка идёт на хост своего бренда —
      иначе на разнесённой платформе прогон вставал бы ложной тревогой
      «токен не работает». Область проверки не расширяется: хост тенанта обязан
      входить в `allowedHosts`, учётные данные в адресе запрещены.
- [x] **Атрибуты обращения как измерение матрицы** — ADR-0019. Условия
      объявляются именованным набором с обязательной областью, правило политики
      называет их явно, аккаунт в условиях — отдельная строка матрицы
      (`alice-a@geo-blocked`) с теми же учётными данными. Логика решения
      платформы не моделируется: сравниваются исходы двух объявленных наборов.
      На полигоне девятый флаг — `POLYGON_DEFECT_GEO_BYPASS`, первый дефект,
      который правами не выражается вовсе; 23 комбинации, расхождений 0.
      Найдено при этом три вещи, каждая из которых давала зелёное на ложном:
      предохранитель достоверности не знал про условия и объявлял **исправный**
      прогон недостоверным; схема правила была нестрогой, и старая сборка молча
      отбрасывала `context`, превращая «запретить в этих условиях» в «запретить
      всегда» (19 находок на чистой платформе); `verify.mjs` печатал сумму
      двух счётчиков, считая находки по телу дважды, — 88 при 76 строках,
      и сверка при этом оставалась зелёной, потому что сравнивает множества.
- [x] 451 признан отказом наравне с 401 и 403: «недоступно по юридическим
      причинам» — решение не обслуживать, а не сбой. Без этого гео-ограничения
      давали бы стену `probe-error` там, где платформа как раз работает.
- [ ] SoD в этом модуле **не делать**: требует записи и состояния, относится
      к другому классу инструментов. Решение зафиксировать, если возникнет спор.

## Готовность к разным контурам

- [x] **ADR-0016: схема аутентификации на аккаунт.** Именованные схемы в корне,
      ссылка по имени у аккаунта. Форма выбрана не для краткости: параметры
      схемы принадлежат контуру, а не аккаунту, и повторённые у каждого они
      разойдутся опечаткой — а опечатку в **параметре** поймать нечем (`opsi` —
      такое же законное имя куки). Опечатка в **ссылке** ловится: имя либо
      объявлено, либо нет. Оба способа сразу не разрешены намеренно.
- [x] Платформа разведена по трём контурам: клиентские аккаунты по Bearer,
      операторская админка по куке `opsid`, кабинет аффилиата по заголовку.
      Токен, предъявленный не тем транспортом, платформа не принимает — иначе
      проверка была бы бутафорской.
- [x] Проверено мутацией: `matchesScheme → return true` делает урезанную
      конфигурацию чистой, то есть сверка транспорта нагружена, а не декоративна.
- [x] Схема каждого аккаунта видна в отчёте (`accounts[].auth`). Без неё
      читатель не отличит «ручка закрыта» от «стучались не тем транспортом».

## Состязательная проверка условий обращения (13 августа 2026)

Запущена по правилу CLAUDE.md — после правок в `src/adapters` и `src/report`.
Пробила **четыре дыры, и все в том, что сделано в тот же день**. Каждая
с воспроизводимым PoC; все воспроизведены мной лично до и после починки.

- [x] **Условия выполняли запись без `--unsafe-methods`** (critical). Заголовок
      `x-http-method-override: DELETE` — и стенд **удалил объект**, пока
      по проводу шёл GET, а отчёт написал `writeMethodsProbed: false`. Гейт
      `SAFE_METHODS` смотрит на метод запроса и такой обход не видит.
      Там же `x-original-url` уводил обращение мимо объявленного пути,
      а `x-forwarded-host` — мимо запрета на подмену хоста.
      Починено тремя слоями: точные имена, префиксы семейств, **проверка
      по значению** (значение равно имени метода → отказ). Последнее ловит
      и вендорский заголовок, о котором никто не слышал.
- [x] **Токен в строке запроса подменял аккаунт** (high). `access_token`
      в условиях — платформа обслуживала обращение как другой аккаунт,
      а отчёт называл исходный. Плюс значение уезжало в отчёт открытым
      текстом: адреса обращений там печатаются.
- [x] **Атрибут переписывал ключ объекта** (high). Вердикт считался
      по объявленному объекту, а спрашивался другой: межтенантная утечка
      легла в отчёт как «свой объект, проверено и совпало» и попала
      в `cellsMatched`.
- [x] **Прогон, не вошедший никуда, давал чистый отчёт и код 0** (high).
      Политика из одних запретов + протухшие токены + отсутствие канареек:
      `findUnauthenticated` молчит по построению, потому что доступным
      не объявлено ничего. Теперь `canariesChecked: 0` — код 2; аккаунты
      без учётных данных из правила исключены.
- [x] **`!!omap` и `!!set` были невидимы обходу спецификации** (medium).
      Внешний `$ref` под таким узлом проезжал мимо барьера, а `paths` под ним
      давал **ноль эндпоинтов без единой ошибки** — сто процентов покрытия
      пустоты. Psych такие документы эмитирует штатно. Теперь отвергаются.
- [x] **`cellsMatched` расходился с числом вердиктов** (low), хотя ADR-0020
      обещает равенство: вычитание включало `not-observed`, у которых
      наблюдения нет вовсе.
- [x] Мелочи оттуда же: запретный список стал `Map` (заголовок `constructor`
      давал сообщение про `[native code]`); имена и значения атрибутов
      проверяются на пригодность к отправке — раньше каждая ячейка такого
      прогона умирала непрозрачным сбоем.

Не пробито (проверялось прицельно): подмена учётного заголовка регистром,
пробелами, юникодом и дублем ключа; подмена `credentialAccountId`; секрет
из `tokenEnv` в отчёте и логах; редиректы; allowlist хостов (18 случаев);
отсутствие тела в `HttpResponse`; троттлинг без режима «без лимитов»;
расхождение `describeCells` с `diffAccess`.

- [ ] Значение атрибута условий всегда попадает в отчёт дословно, и env-варианта
      для него нет. Оператору, которому нужна подпись устройства или партнёрский
      ключ в условиях, инструмент не оставляет места, кроме открытого текста
      в конфигурации. Сегодня это компенсируется запретом известных носителей
      учётных данных, но правильное решение — `valueEnv` рядом с `value`.

## Холодное чтение README и пути «от нуля до прогона» (13 августа 2026)

## Блокеры прогона на чужой платформе

Лежали вперемешку с остальным, отчего читались как равные. Это не равные:
без них инструмент запускает только автор.

- [x] ~~Схема аутентификации~~ — четыре схемы в конфигурации: `bearer`, `header`,
      `cookie`, `basic` (ADR-0008).
- [x] **Подпись запроса — случай библиотеки, и теперь это правда** (ADR-0018).
      Прежняя запись утверждала, что потребитель библиотеки свою схему
      реализовать может: порт экспортирован. **Утверждение было неверным** —
      `headersFor(accountId)` не видел ни метода, ни адреса, а `runner` вдобавок
      вычислял заголовки один раз на аккаунт. Подписать было нечего и нечем.
      Порт получил `SignedRequest { method, url }` и вызывается на каждое
      обращение, включая канареечное. Формат подписи в конфигурации
      по-прежнему не описывается — вслепую он получился бы совпадающим
      с настоящей платформой наполовину, а наполовину верная подпись даёт 401
      везде, то есть отчёт «доступа нигде нет».
      Пример из руководства проверен на **собранном** пакете: `tsc --noEmit`
      с кодом 0 и живой запуск, а не чтение кода.
- [ ] Схема `signature` в конфигурации — когда появятся **две** платформы
      с подписью. Одна общего не покажет, а мини-язык канонизации, выведенный
      из одной, станет плохим шаблонизатором. Условие пересмотра — в ADR-0018.
- [x] ~~Селекторы эндпоинтов по шаблону~~ — закрыто, платформа переведена
      на `path: /v1/admin/**`, 19 комбинаций сошлись.
- [x] **Документация пользователя** — [docs/guide.md](docs/guide.md) и
      [docs/report.md](docs/report.md). Написаны **от непониманий холодного
      читателя**, а не от структуры конфигурации: иначе вышел бы справочник
      по полям вместо руководства. Примеры из руководства проверены разбором.
- [x] Документация пользователя проверена холодным чтением дважды — вторым
      и третьим, оба раза вместе с настоящим отчётом. Оценка отчёта выросла
      с 2 из 5 до 3 из 5; вопросы, снятые руководствами, во второй раз
      не повторились.
- [ ] README и путь «от нуля до первого прогона» холодным чтением **не**
      проверялись ни разу: читали отчёт и руководства, а не установку.
      Это и есть критерий выхода фазы 4 — посторонний по README доводит
      `npx barbican` до осмысленного прогона.
- [x] **Допущение проверено холодным чтением.** Настоящий отчёт дефектного
      прогона отдан читателю без доступа к проекту (только два файла, запрет
      открывать что-либо ещё). Самооценка отчёта: **2 из 5**.

Исправлено сразу, всё подтверждено измерением:

- [x] **`bySeverity` не считала находки проверок** — сводка показывала high: 5
      там, где их 11. Дашборд по сводке терял шесть находок, и в их числе самую
      эксплуатируемую. Это был счётный дефект, а не вопрос вкуса.
- [x] Канарейки — вердикт поимённо вместо счётчика. «Проверено 7» без «прошли ли»
      неотличимо от молча провалившихся канареек.
- [x] Сводка врала арифметикой: «80 пар, эндпоинтов 6, аккаунтов 8», а 6×8=48.
      Ячейка — тройка «аккаунт × эндпоинт × объект», так и написано.
- [x] `cache-control` и `date` перестали редактироваться. Первый меняет **оценку
      ущерба**: межтенантная утечка с `public` размножается через CDN. Второй —
      единственная зацепка сопоставить находку с логом сервера. Учётных данных
      не несёт ни тот, ни другой; `set-cookie` по-прежнему режется.

Осталось из холодного чтения, по убыванию отдачи:

- [x] **Вводные в отчёте** — секция `inputs`: раскрытая политика (та, что
      выносила вердикты, а не та, что в файле), дерево тенантов, вид схемы
      аутентификации. Значений учётных данных нет и быть не может.
- [x] **Воспроизведение у каждой находки** — метод и адрес с подставленными
      значениями. Соединение делается при сборке отчёта, ядро об адресах
      по-прежнему не знает.
- [x] Находка называет правило: `ruleIndex` указывает в `inputs.policy.rules`.
      Отсутствие поля — содержательный ответ «сработал `fallback`», а не пропуск.
      Номер указывает на последнее подошедшее правило, потому что побеждает оно.
- [x] **Таксономии слиты.** Один список `findings`, поле `source` различает
      способ обнаружения. Различие способа больше не выдаётся за различие
      природы находки.
- [x] Из этого само собой закрылось три симптома: `byKind` считает проверки,
      `bySeverity` не нуждается в заплатке, группировка ADR-0015 работает
      на всём. Шесть клонов схлопнулись в одну сигнатуру — проверено прогоном:
      33 находки, 5 сигнатур вместо прежних четырёх плюс шести строк.
- [x] `defects[].observations` переименовано в `violations`: одно слово в двух
      смыслах читалось как «дефект наблюдался на 10 пробах из скольких-то».
- [x] `identicalBody` утверждал больше, чем проверено: совпали дайджесты, а не
      тела. Переименовано в `bodyDigestsEqual`; заголовок находки теперь тоже
      говорит о дайджесте, а не об «одинаковом ответе».
- [x] `tenantScoped` назывался свойством API, а кодировал объявление оператора:
      у `orders.read` его не было, хотя он тенант-скоупный по смыслу и как раз
      течёт. Переименовано в `responseMustDifferByTenant` — сквозно, включая
      ключ в `bodySignals`. См. уточнение в ADR-0011.
- [x] Знаменатель покрытия в секции `coverage`: эндпоинтов опрошено из
      скольких, ячеек пронаблюдено и не пронаблюдено, почему не опрашивались.
- [x] Сказано, где проверка не проводилась: `bodiesComparedOn` называет ручки
      поимённо, `writeMethodsProbed` — выполнялись ли методы записи. На всех
      прочих ручках отсутствие находки означает «не сравнивали».
- [x] Сентинел убран: `tenant` у аккаунта необязателен, аккаунт без него —
      вне тенантов. Отношение к любому объекту — `foreign-tenant`, шестое
      значение не заводилось намеренно: оно **молча сузило бы существующие
      правила**, потому что `scope: foreign-tenant`, написанное как «постороннему
      нельзя», перестало бы покрывать анонима, и ячейка ушла бы в `fallback`.
      Ровно тот механизм пряток находки, против которого писался ADR-0013.
- [x] В `examples/minimal/` аноним был приписан к `tenant-a` — ошибка хуже
      сентинела: он числился **своим** для настоящего тенанта.
- [x] Устаревшее предупреждение в README о плоских тенантах переписано.
      Иерархия реализована, но она объявляется человеком — без объявленного
      дерева прежний режим отказа остаётся, и об этом сказано прямо.
- [x] `schemaVersion`, `runId` и `configDigest`. Отпечаток считается по
      разобранной конфигурации, а не по тексту: комментарии и отступы на прогон
      не влияют, а на хеш текста влияли бы.
