# План

Режим работы: соло, 8–10 часов в неделю. Сессии по 2–3 часа.

## Модуль 1 — harness для RBAC и изоляции тенантов

Вход: OpenAPI-спека или список эндпоинтов плюс набор аккаунтов с разными ролями и
тенантами. Инструмент перебирает матрицу «роль × эндпоинт», строит фактическую матрицу
доступа, сравнивает с ожидаемой и показывает расхождения: privilege escalation,
BOLA/IDOR, cross-tenant утечки.

| Сессия | Содержание | Статус |
|---|---|---|
| 1 | Каркас: конфиги, хуки, CI, ADR, реестр проверок, smoke-тест | готово |
| 2 | Ядро: типы и чистые функции матрицы и диффов, фикстуры, тесты | следующая |
| 3 | Адаптеры: парсер OpenAPI (внешние `$ref` отключены + тест), HTTP через global fetch, троттлинг | |
| 4 | CLI и вывод: команды, обязательный scope, `--unsafe-methods`, JSON-отчёт, редакция | |
| 5+ | Integration: docker-compose с полигонами, валидация ядра против известного ground truth | |

## Модуль 2 — evidence-pack по внешним стандартам

Набор проверок, замапленных на пункты внешних стандартов, с генерацией отчёта.
Архитектурно уже подготовлен: поле `standards` в интерфейсе `Check` и реестр проверок.
Добавляется регистрацией новых проверок, а не изменением ядра.

Начинать после того, как ядро Модуля 1 стабилизируется и будет проверено против
полигонов с известным ground truth.

## Границы каталогов

Создаются в той сессии, где появляется первая реальная реализация — пустых каталогов
«на будущее» в репозитории нет.

| Каталог | Назначение | Появится |
|---|---|---|
| `src/core` | Чистые функции: матрица, диффы, проверки | есть |
| `src/adapters` | HTTP-клиент, парсер спек, троттлинг — за портами | порты есть, реализации в сессии 3 |
| `src/io` | Чтение спек и аккаунтов, запись JSON | сессия 4 |
| `src/report` | Рендер JSON в HTML/PDF отдельным шагом | Модуль 2 |
| `tests/fixtures` | Фикстуры ядра, без сети | сессия 2 |
| `tests/integration` | Прогоны против полигонов | сессия 5 |

## Вне области ближайших сессий

Публикация в npm и релизный процесс, monorepo и workspaces, Docker-инфраструктура
до сессии 5.
