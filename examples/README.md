# Примеры

## `minimal/`

Наименьшая рабочая конфигурация: два тенанта, три аккаунта (включая анонимный),
три ручки. Комментарии объясняют, зачем каждое поле, а не что оно означает.

Стенда здесь нет — это шаблон, с которого начинают. Он разбирается и проходит
сверку ссылок, но `baseUrl` указывает в пустоту: подставьте свой.

```bash
barbican run --config examples/minimal/barbican.run.yaml --endpoints examples/minimal/endpoints.yaml
```

Токены берутся из окружения по именам из `tokenEnv`:

```bash
TOKEN_ALICE=… TOKEN_CAROL=… barbican run --config examples/minimal/barbican.run.yaml --endpoints examples/minimal/endpoints.yaml
```

## Работающий пример целиком

`polygon/` в корне репозитория — не пример, а стенд для проверки самого
инструмента: мультитенантный API с четырьмя переключаемыми дефектами,
машиночитаемым оракулом и скриптом сверки. Смотреть туда стоит, когда нужен
не шаблон, а рабочая конфигурация против живого сервера.

```bash
node polygon/verify.mjs
```

## Что стоит понять до первого прогона

**Ожидаемый доступ объявляете вы.** Он не выводится из спецификации
проверяемого API: спека порождается из того же кода, и вывод из неё означал бы
сравнение реализации с самой собой (ADR-0006). Пустая политика даст прогон
без единой находки — и это будет означать «ничего не объявлено», а не «всё чисто».

**Код возврата 2 — не ошибка запуска, а недоверие к прогону.** Он означает,
что результату нельзя верить: токен протух, потолок обращений исчерпан,
наблюдений нет вовсе. Отличать его от честного нуля важнее, чем кажется:
«находок нет» и «ничего не проверено» выглядят в отчёте одинаково.

**Канарейки не бутафория.** Аккаунт без канарейки проверить нельзя: если все
его обращения получили отказ, инструмент не может отличить исправную защиту
от протухшего токена.
