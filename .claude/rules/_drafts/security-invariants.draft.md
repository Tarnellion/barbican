# Инварианты безопасности

Полный текст и обоснование — CLAUDE.md и ADR-0005. Здесь то, что легко нарушить
незаметно, увлёкшись задачей.

## Не ослаблять без ADR

- **`SAFE_METHODS`.** Без `--unsafe-methods` только GET и HEAD. Добавление метода в
  константу меняет поведение по умолчанию на чужом стенде.
- **Отсутствие тела в `HttpResponse`.** Это не пропущенное поле. Добавить тело «чтобы
  удобнее отлаживать» — значит сделать файл отчёта носителем PII.
- **Отключённый резолвинг внешних `$ref`.** Ни http, ни файловая система. Включение
  превращает разбор спецификации в SSRF-примитив. Тесты-доказательства не удалять и
  не помечать `skip`.
- **Троттлинг.** Порт, а не опция. Режима «без лимитов» быть не должно.
- **Обязательный scope.** Без allowlist хостов инструмент отказывается работать.
  Дефолтного «разрешить всё» не заводить.
- **`minimumReleaseAge`, `strictDepBuilds`, пустой `allowBuilds`.** Установка упала
  из-за lifecycle-скрипта — это не помеха, а срабатывание защиты. Правильная реакция —
  прочитать скрипт и выполнить нужное действие явной командой, а не добавить пакет
  в allowlist.

## Всегда

- Пути редакции чувствительных данных — только хардкод, никогда из пользовательского ввода.
- Секреты — только через переменные окружения. Ни в репозиторий, ни в логи, ни в отчёты.
- Новая зависимость — только после проверки (см. черновик `dep-vetting`).
